# 将来DB化メモ

初期版はTypeScriptの設定データで動作し、保存処理を持ちません。Supabase／PostgreSQLへ移行する場合は、計算ロジックを変更せず入力データの取得元だけを置き換える設計とします。

## 推奨テーブル

### stores

店舗マスター。`management_partner`（アッタ／NaS／LIVE COLOR）、運営区分、開設月、スターターキット導入日、情報参照URLを保持します。

### store_monthly_operations

店舗×月の仕上げ、水洗い、撮影、リチェック実台数、担当人数、枠数、実績売上、実績直接原価を保持します。実績と予算・予測は `data_kind` で区別します。

### pricing_versions

ガリバー→アッタ、アッタ→NaS、NaS→スタッフの単価を、適用開始日・終了日付きで版管理します。

### operating_cost_settings

スターターキット単価、NaS月次用具費、会計表示方法、税率、リチェック換算率を保持します。

### expansion_scenarios

シナリオ名、店舗数、展開方法、各店舗の開設予定月、処理台数、単価版、作成者を保持します。

### monthly_cash_flows

確定したシナリオの月次計算結果をスナップショット保存する場合に使用します。入力条件と計算ロジックのバージョンを併記し、再現可能性を確保します。

## 運用上の要点

- 金額は整数円、換算率・構成比はdecimalで保持する
- 店舗・単価は物理削除せず有効期間で管理する
- 実績値と予測値を同じレコードで上書きしない
- 計算結果より入力条件を正として、必要に応じて再計算する
- 権限は管理者、編集者、閲覧者の3段階を基本とする
- 変更履歴に変更者、変更日時、変更前後の値を残す
